# Overworked — инструкции для Claude

## Настройка клона (проверить в начале каждой сессии)

- `git config core.hooksPath` должен возвращать `tools/hooks`. Если пусто — выполни
  `git lfs install` и `git config core.hooksPath tools/hooks` и скажи об этом пользователю.
- Если спрайты в `Assets/` или `External/` — текстовые LFS-указатели (`version https://git-lfs…`),
  выполни `git lfs pull`.

## Работа

- Работай в ветке своей роли (`p1/…`–`p4/…`, см. `docs/TASKS.md`), не в `main`;
  уточни у пользователя, кто он — P1, P2, P3 или P4. Не трогай файлы чужой зоны.
- Перед пушем — `git fetch` и `git merge origin/main` (иначе хук остановит пуш).
- PR с красной проверкой `checks` на GitHub не мержить и не предлагать мержить.
- Перед работой прочитай `CONTRIBUTING.md` (правила) и `docs/PROJECT_PASSPORT.md` (дизайн и архитектура).
- Соблюдай правила комментариев из `CONTRIBUTING.md`, раздел 2: `/// <summary>` на классах
  и неочевидных публичных методах, `[Tooltip]` на настраиваемых полях, комментарии «почему»
  над неочевидной логикой. Не комментируй каждую строку. Комментарии — на русском.
- Новая система → создай `docs/systems/<Система>.md` по шаблону из `CONTRIBUTING.md`.
- Изменил дизайн или архитектуру → обнови паспорт в том же коммите.
- Тексты игры — на английском (из `docs/narrative/NARRATIVE_EN.md`) и в ScriptableObject
  (`Assets/_Project/Data/`), не в коде. Меняется русский нарратив — обнови и английский.
- Перед пушем работает хук `tools/hooks/pre-push` (`tools/checks.py`); не обходить его `--no-verify`.
  Если в репозитории есть `Assets/`, перед коммитом кода запускай `python tools/check_compile.py`.
