# SanityManager и SanityBarUI

**Владелец:** Программист 4

**Что делает:** хранит рассудок 0..100. Меняется только сценарными событиями: галлюцинация задаёт
целевое значение (`SetSanity(70)`), шкала плавно «стекает» к нему (ease-in-out): `smoothTime` (1 с)
плюс `extraTimePer100` (2 с) за каждые 100 пунктов падения — 90 → 70 ≈ 1.4 с, 25 → 0 ≈ 1.5 с.
`SanityBarUI` показывает нарисованную полосу без процентов (спрайты `Art/UI/Sanity/Resources`:
`SanityBar_Frame` — рамка с тёмной подложкой, `SanityBar_Fill` — белая маска светлой части).
В момент падения: полоса вздрагивает (сила — от размера потери), за заполнением тянется
пульсирующий красный след потерянной части (стоит 0.5 с, потом догоняет). Ниже 30 % заполнение
краснеет и полоса слегка «плывёт». Мгновенные установки (`SetSanityInstant`) — без следа и тряски.

**Как подключить:** `SanityManager` уже лежит в `_Systems`. Шкала — объект `HUD/SanityBar` в `_Systems`
(вёрстка P3, левый верхний угол): на нём `SanityBarUI`. При старте он сам достраивает слои
Frame → Trail → Fill, берёт спрайты из Resources и ставит размер 300×37 (пропорция картинки) —
поэтому пересборка HUD (Build HUD) ничего не ломает.
Стартовое значение этажа выставляет `FloorSettings` (100 / 90 / 50).

**Публичный API:**

| Метод / событие | Что делает |
|---|---|
| `SetSanity(float 0..100)` | новое целевое значение, шкала плавно догоняет |
| `SetSanityInstant(float)` | без анимации (загрузка этажа, отладка) |
| `Current`, `Current01`, `Target` | текущее 0..100, текущее 0..1, цель |
| `event OnSanityChanged(float current01)` | вызывается каждый кадр, пока шкала движется |
| `event OnSanitySnapped(float current01)` | значение выставлено мгновенно — анимировать потерю не нужно |

**Отладка:** в `Sandbox_P4` объект `P4_Debug` (`HorrorDebugKeys`): 1–5 — рассудок 90/70/50/25/0, 0 — сразу 100.

**Зависит от:** ничего.
