# OVERWORKED — паспорт проекта и техническая структура

Unity 6 (URP 2D) • 2D Psychological Horror • PC • Game Jam

> Исправленная версия исходного PDF-паспорта: устранены противоречия, добавлены
> недостающие технические детали и решения команды (раздел «Принятые решения» в конце).

**Язык игры — английский** (все тексты, сообщения, субтитры, UI).

---

## 1. Общая информация

| | |
|---|---|
| Название | Overworked |
| Жанр | 2D Psychological Horror / Narrative |
| Платформа | PC (Windows) |
| Движок | Unity **6000.5.6f1**, URP 2D — у всей команды строго одна версия |
| Ввод | Input System (новый) |
| Команда | 4 программиста + 2 художника |
| Вид | 2D side view |

**Управление**

| Действие | Клавиша |
|---|---|
| Движение | A / D и ← / → (прыжка и бега нет) |
| Взаимодействие | E |
| Фонарик | F (доступен с Floor_02) |
| Телефон | UI-кнопка **и** клавиша Tab |
| Пауза | Esc |

Пока открыт телефон, Денни не двигается (ввод движения блокируется), мир не на паузе.

**Главная идея.** Игрок управляет Денни — офисным работником, который после очередного
периода переработок пытается просто добраться домой. Обычный офис постепенно превращается
в психологический кошмар. Маршрут: Этаж 3 → Этаж 2 → Этаж 1 → Белая комната.

## 2. Главная игровая цель

Игрок выполняет обязательные задания, которые передаёт Макс через телефон. Лестница на
этаже **заблокирована**, пока не выполнены все обязательные задания этажа (при попытке
воспользоваться — короткая реплика/подсказка). На предыдущий этаж вернуться нельзя.
Комнаты находятся внутри сцены текущего этажа.

## 3. Основной игровой цикл

```
Исследование → Сообщение Макса → Новое задание → Поиск объекта / выполнение
→ Задание выполнено → Изменение рассудка / событие → Новая аномалия
→ Следующее сообщение → … → Все обязательные задания → Лестница открыта → Следующий этаж
```

## 4. Структура игры

```
MAIN MENU → FLOOR 03 → FLOOR 02 → FLOOR 01 → (FINAL EVENT) → WHITE ROOM → (CREDITS)
```

Unity-сцены: `MainMenu`, `Floor_03`, `Floor_02`, `Floor_01`, `WhiteRoom`.

- **FINAL EVENT** — не сцена, а скриптовое событие в конце `Floor_01`.
- **CREDITS** — не сцена, а UI-панель в конце `WhiteRoom`, после неё возврат в `MainMenu`.
- Комнаты не являются отдельными сценами.

## 5. Этаж 3

Самый нормальный этаж. Рассудок 100 → 90. Комнат нет — только коридор.
Boss: 2 сообщения (фон, не задания). Max: 1–2 сообщения (задания).
Офис: рабочие столы, компьютеры, шкафы, документы, кофе, окна, обычное освещение
и небольшие странности. После обязательного задания открывается лестница.

## 6. Этаж 2

Рассудок 90 → 50. Одна комната (`Room_201`). Boss: 1 сообщение. Max: 3 сообщения.
С начала этажа фонарик уже в руках у Денни (подбирать не нужно).
**Макс пишет очень странно**: текст ещё читаемый, но тон и содержание сбоят —
неуместные фразы, повторы, знает то, чего знать не может. Это подготовка к Floor_01,
где сообщения превращаются в глитч-символы. Сильнее аномалии:
силуэт в отражении, надпись на стене, паук, глаза в тёмном углу, исчезающие предметы,
искажения камеры и т. п.

**Сцена с именем.** В середине этажа Денни садится на стул (интерактивный объект `Chair`)
и спрашивает: «Как нас зовут?». Игрок вводит имя в поле ввода. Имя хранится в
`GameState.PlayerName` и подставляется в тексты через плейсхолдер `{name}`
(сообщения, диалоги, Белая комната). Пустое имя не принимается, длина ≤ 16 символов.

## 7. Этаж 1

Рассудок 50 → 0. Boss больше не пишет. Max продолжает писать и становится всё
более странным — игрок постепенно понимает, что Макс является частью галлюцинации.
**Раскрытие:** на этом этаже сообщения Макса начинают приходить странными символами
(глитч-текст: смесь нормальных слов и мусорных символов, к концу этажа — почти
полностью нечитаемые). Задание при этом остаётся понятным из Objective-карточки.
Две комнаты:

- `Room_101` — искажённый человек сидит и бессвязно бормочет. При E он сжимается
  в точку и исчезает (`PersonInteractable`).
- `Room_102` — финальное задание: мини-игра на компьютере. Её завершение запускает FINAL EVENT.

**Финальная мини-игра — Tiny UFO** (готовая игра автора, репозиторий `Gekataaaaa/tiny-ufo`).
Игрок садится за компьютер в `Room_102`, открывается упрощённая версия:
- меню только с кнопками **Play** и **Quit** (Quit — выйти из компьютера, задание не выполнено);
- **одна волна** — копия четвёртой волны Tiny UFO;
- победа в волне = задание выполнено → FINAL EVENT; проигрыш → волна заново.

Технически: переносится как отдельный модуль `Assets/_Project/MiniGame/` (свои скрипты,
спрайты, звуки, префаб), запускается поверх сцены `Floor_01` (отдельная камера/Canvas
или additive-сцена `MiniGame_TinyUFO`), управление Денни на это время блокируется.
Лишнее из Tiny UFO (прогресс, способности за пределами волны 4, настройки, лидерборд)
не переносится.

Лестницы вниз на этаже 1 **нет** — переход в Белую комнату только через финальное событие.

## 8. Финальное событие и White Room

```
Завершение мини-игры → Sanity → 0 → Final Screamer → загрузка WhiteRoom
```

**Финальный скример** — фантомная фигура офисного работника, похожего на самого Денни
(двойник): резкое появление вплотную к камере + громкий звук, затем чёрный экран.

Белая комната — отдельная сцена. Нет стен и потолка, только белое пространство и линия
пола. HUD (рассудок, objective, телефон) скрыт, пульс остаётся. Денни может двигаться
только вправо. Он обращается непосредственно к игроку (по имени), спрашивает, где он,
что происходит и где находится игрок. Появляется кровать, Денни ложится (автоматически
при подходе). Пульс падает 40 → 30 → 20 → 10 → 0, затем длинный beep, тишина и титры.
Никакого дополнительного морального текста.

## 9. Рассудок

Процент рассудка игрок НЕ видит — только шкала в левом верхнем углу. Рассудок меняется
**событийно**, а не от расстояния или времени. После события целевое значение меняется,
шкала плавно приходит к нему примерно за 1 секунду.

```
Event → targetSanity = clamp(targetSanity - damage, floorMin, 100)
      → SanityBar плавно догоняет target (~1 сек)
```

**Границы этажа.** У каждого этажа есть `floorMin` (90 / 50 / 0). Рассудок не может
упасть ниже `floorMin` текущего этажа, а при переходе на следующий этаж принудительно
выставляется в `floorMin` предыдущего (если игрок пропустил необязательные события).
Так значения 100 → 90 → 50 → 0 гарантированы вне зависимости от того, что игрок нашёл.

Конкретные потери балансируются на тестах. Примеры событий: силуэт, странная записка,
сильная галлюцинация, завершение задания, финальное событие.

## 10. Архитектура Sanity

```
SanityManager
├── CurrentSanity / TargetSanity / FloorMin
├── ApplyDamage(amount)
├── SetFloorMin(value)
├── (Update) плавный переход Current → Target
└── event OnSanityChanged(float current01)
       ├── SanityBarUI
       ├── HallucinationManager   (пороги для trigger-based галлюцинаций)
       ├── HeartbeatManager       (базовый BPM)
       ├── PostFXController       (виньетка, шум, аберрация)
       └── AudioManager           (гул, искажения)
```

## 11. Сердцебиение

Heartbeat — не здоровье и не HP, а визуально-звуковой индикатор напряжения.
В правом верхнем углу — иконка и BPM.

- **Базовый BPM зависит от рассудка**: 100 % → ~70 BPM, 0 % → ~120 BPM (подбирается).
- **Спайки**: во время аномалий пульс временно повышается (+20…+40) и за несколько
  секунд возвращается к базовому.
- **Финал**: в WhiteRoom базовая логика отключается, пульс скриптово идёт
  40 → 30 → 20 → 10 → 0 и переходит в непрерывный beep.

## 12. Телефон

Открывается игроком вручную (кнопка или Tab), автоматически не открывается.
Контакты Boss и Max, сообщения можно перечитывать, отвечать нельзя. Новое сообщение —
уведомление (иконка на кнопке телефона + короткий тост) и звук.
**История сообщений сохраняется между этажами.**

## 13. Система сообщений и заданий

```
Триггер сообщения → MessageManager.Deliver(msg) → уведомление
   если msg.LinkedObjective → ObjectiveManager.Start(objective) → Objective UI
Игрок выполняет задание → ObjectiveManager.Complete()
   → ☑ в UI, SanityManager.ApplyDamage, HallucinationManager (опц.), следующее сообщение
```

Триггеры доставки сообщений: старт этажа, завершение задания, вход в зону (trigger),
таймер после предыдущего сообщения. Boss-сообщения — фоновые (без задания).

Под HUD-пульсом в правом верхнем углу — карточка Objective с чекбоксом.
После выполнения чекбокс отмечается, через ~2 сек карточка сменяется следующей.

## 14. Interaction System

Универсальная кнопка E. Игрок подходит к объекту, получает подсказку `[E] <действие>`
(текст задаётся на объекте: «Открыть», «Прочитать», «Сесть»…) и запускает действие.
Если в зоне несколько объектов — выбирается ближайший.

| Объект | Действие |
|---|---|
| Drawer | `Open()` |
| Note | `ShowText()` |
| Computer | `StartEvent()` |
| Person | `TriggerHallucination()` |
| Chair | `SitAndAskName()` |
| Pickup (предмет задания) | `PickUp()` — предмет исчезает со сцены, шаг задания закрыт |
| Door | `EnterRoom()` / `ExitRoom()` |
| Stairs | `ChangeFloor()` — только если обязательные задания выполнены |

Все объекты реализуют `IInteractable` и могут через `ObjectiveTarget` сообщать
`ObjectiveManager`, что шаг задания выполнен — без прямых ссылок друг на друга.

## 15. Комнаты

Каждая комната — дочерний объект сцены этажа. У двери в коридоре и у двери в комнате
есть точка появления игрока:

```
Corridor/Doors/Door_201 ── ссылка ──► Room_201/EntryPoint
Room_201/ExitDoor       ── ссылка ──► Corridor/Doors/Door_201/ReturnPoint
```

```
E → Fade Out → Player.position = Room_201/EntryPoint → переключить камеру → Fade In
E → Fade Out → Player.position = Door_201/ReturnPoint → переключить камеру → Fade In
```

Комната в той же сцене, загрузка новой Unity Scene не требуется. Комнаты размещаются
в стороне от коридора (например, ниже по Y), чтобы камера их не захватывала.

## 16. Камера

Cinemachine. Основная виртуальная камера следует за Денни с небольшим смещением
в сторону движения. У коридора и у каждой комнаты свой `CinemachineConfiner2D`
(границы); при входе в комнату включается её виртуальная камера. Тряска камеры —
через `CinemachineImpulseSource`.

## 17. Hallucination System

Два типа:
- **scripted** — строго по сценарию (вызываются из событий/заданий);
- **trigger-based** — зависят от зоны и порога рассудка, срабатывают один раз.

Галлюцинации не наносят физического урона, а создают психологическое давление.

```
Player enters trigger (и sanity ≤ порога) → Hallucination Event
→ Sound + Visual + Heartbeat spike (+ опц. Sanity damage) → Event ends
```

## 18. Примеры галлюцинаций

Два основных визуальных типа:
- **Чёрные силуэты** — фигуры людей, полностью чёрные, без деталей.
- **Галлюцинации с предметами** — предметы исчезают, меняются, оказываются в другом месте,
  включаются сами.

Полный список идей: силуэт; человек впереди; глаза в темноте; паук; фигура в отражении; исчезновение или
изменение предмета; внезапная тень; рывок камеры; искажение изображения; странный звук;
предмет в другом месте; самовключившийся компьютер; надпись на стене; погасший свет;
отключение фонарика.

## 19. Компьютер

```
E → чёрный экран → построчно появляется «DEAD DENNY» (4 строки) → экран гаснет
```

Событие не получает прямого объяснения.

## 20. Фонарик

Появляется на Floor_02 автоматически — с начала этажа фонарик уже в руках у Денни
(на Floor_03 его нет). F включает и выключает (2D Spot Light). На низком рассудке
может мерцать или отключаться во время важных событий. Не является обязательным
инструментом прохождения — уровни должны быть проходимы без него.

## 24. ScriptableObjects

```
Data/
├── Messages/
│   ├── F3_Boss_01, F3_Boss_02, F3_Max_01 …
│   └── F2_… , F1_…
├── Objectives/
│   ├── F3_CheckDocuments
│   └── …
├── Dialogues/
└── Hallucinations/
```

- **MessageData**: `Sender` (Boss/Max), `Text` (поддерживает `{name}`), `Floor`,
  `LinkedObjective` (пусто = фоновое сообщение), `DelayAfterPrevious`.
  Поле `IsTaskMessage` не нужно — вычисляется как `LinkedObjective != null`.
- **ObjectiveData**: `Id`, `Title`, `IsRequired`, `SanityDamage`, `NextMessage`.
- Префикс этажа в имени ассета (`F3_`, `F2_`, `F1_`) — чтобы не путаться.

Контент хранится отдельно от кода — тексты могут править не-программисты.

## 25. Связь систем

```
MessageManager ── F2_Max_03 ──► ObjectiveManager.Start("Найти документы") ──► ObjectiveUI
Player ── E ──► Drawer (ObjectiveTarget) ──► ObjectiveManager.Complete()
                                              ├── ObjectiveUI → ☑
                                              ├── SanityManager.ApplyDamage(X)
                                              ├── HallucinationManager → Event (опц.)
                                              └── MessageManager → следующее сообщение
```

Системы общаются через C#-события / методы менеджеров, без `FindObjectOfType`
и без прямых ссылок «объект знает про UI».

## 26. GameManager и постоянные системы

GameManager не должен становиться гигантским контроллером. Он хранит `GameState`
(CurrentFloor, PlayerName, флаги) и глобальные ссылки.

Между сценами должны жить рассудок, история телефона, имя игрока и HUD.
Поэтому: префаб **`_Systems`** (GameManager, SanityManager, HeartbeatManager,
PhoneManager, MessageManager, ObjectiveManager, AudioManager, HUD Canvas) создаётся
один раз через `Bootstrap` и помечается `DontDestroyOnLoad`. В сценах этажей
этих объектов нет — только окружение, игрок, камера и контент этажа. Для запуска
любой сцены прямо из редактора `Bootstrap` сам подгружает `_Systems`, если его нет.

## 32. Правила работы с git

> Полные правила (документация, комментарии в коде, git, чеклист PR) —
> в [CONTRIBUTING.md](../CONTRIBUTING.md). Ниже — краткая выжимка по git.

- Один `.gitignore` для Unity (Library/, Temp/, Obj/, Logs/, UserSettings/, Build/).
- Asset Serialization = Force Text, Visible Meta Files; `.meta` всегда коммитятся вместе с ассетом.
- **Сцену этажа редактирует один человек одновременно** — договариваться в чате.
  Всё остальное делается в префабах и в своей `Sandbox_<имя>`.
- Ветки: `main` — всегда запускается; фичи — `feature/<что>`, мелкие частые PR.
- Крупные бинарники (wav/psd) — через Git LFS, если файлы > ~50 МБ.

## Принятые решения

1. **Финальная мини-игра** — Tiny UFO: меню Play / Quit, одна волна (копия 4-й). См. раздел 7.
2. **Компьютер** — на экране «DEAD DENNY». См. раздел 19.
3. **Фонарик** — на Floor_02 автоматически в руках у Денни, без подбора.
4. **Инвентаря нет, но предметы подбирать можно.** Подобранный предмет просто исчезает
   со сцены и закрывает шаг задания (флаг в `GameState`), без UI инвентаря.
   Например, `Objective_FindKey`: подобрал ключ → задание выполнено → можно идти дальше.
5. **Реплики Денни** — субтитры внизу экрана.
6. **Язык** — английский.
7. **Раскрытие Макса** по этажам: Floor_03 — пишет нормально; Floor_02 — очень странно,
   но читаемо; Floor_01 — глитч-символы (только здесь).
8. **Галлюцинации и скример** — чёрные силуэты и галлюцинации с предметами; финальный
   скример — фантомная фигура работника, похожего на Денни.
