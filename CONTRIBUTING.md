# Правила проекта Overworked

Обязательны для всех участников (и для AI-ассистентов). Цель — чтобы любой из команды
мог открыть чужую систему и за пару минут понять, что она делает и как её подключить.

## 1. Документация

**Источник правды — [паспорт проекта](docs/PROJECT_PASSPORT.md).**

- Меняешь дизайн или архитектуру (новая система, новый тип объекта, другая логика
  рассудка и т. п.) — **обновляешь паспорт в том же коммите/PR**. Паспорт не должен
  расходиться с кодом.
- У каждой системы есть короткий документ `docs/systems/<Система>.md`, который ведёт
  её владелец (см. паспорт, раздел 28). Шаблон:

  ```markdown
  # SanityManager
  **Владелец:** Программист 4
  **Что делает:** одной-двумя фразами.
  **Как подключить:** что положить в сцену / на объект, какие поля заполнить.
  **Публичный API:** методы и события, которыми пользуются другие системы.
  **Зависит от:** какие системы использует.
  **Известные ограничения / TODO:** …
  ```

  Документ создаётся вместе с первой рабочей версией системы, а не «потом».
- `README.md` обновляется на вехах (появился играбельный этаж, готов билд и т. д.):
  раздел «Статус» должен быть актуальным.
- Тексты для игры (сообщения, задания, диалоги) живут в ScriptableObject в `Data/`,
  а не в коде.

## 2. Комментарии в коде

Комментарии пишем **периодически и по делу**: не на каждую строку, но так, чтобы
файл читался без автора рядом. Язык комментариев — **русский**, имена в коде — английские.

**Обязательно:**

1. **Шапка класса** — `/// <summary>` над каждым классом: что это и где используется.
   ```csharp
   /// <summary>
   /// Хранит рассудок игрока и плавно ведёт шкалу к целевому значению.
   /// Живёт в префабе _Systems, переживает смену сцен.
   /// </summary>
   public class SanityManager : MonoBehaviour
   ```
2. **Публичные методы и события** — `/// <summary>`, если по имени не очевидно всё:
   единицы измерения, когда вызывать, что будет при повторном вызове.
   ```csharp
   /// <summary>Уменьшает целевой рассудок. Не опускает ниже floorMin текущего этажа.</summary>
   public void ApplyDamage(float amount)
   ```
3. **Поля в инспекторе** — `[Tooltip("...")]` на каждом `[SerializeField]`, который
   будут настраивать другие люди (художники, дизайнеры уровней).
   ```csharp
   [Tooltip("За сколько секунд шкала догоняет новое значение")]
   [SerializeField] float smoothTime = 1f;
   ```
4. **Неочевидная логика** — короткий комментарий над блоком: *почему* так, а не *что*
   делает строка. Магические числа, обходы багов Unity, порядок вызовов, тайминги.
   ```csharp
   // Ждём кадр: Cinemachine обновляет камеру в LateUpdate, иначе fade мигнёт старым кадром.
   yield return null;
   ```

**Не надо:**

- комментировать очевидное (`i++; // увеличиваем i`);
- оставлять закомментированный старый код — для истории есть git;
- писать `TODO` без имени: только `// TODO(имя): что сделать`.

## 3. Код

- Один класс — один файл, имя файла = имя класса. Скрипты — в папке своей системы
  (`Assets/_Project/Scripts/<Система>/`).
- Именование: классы и методы `PascalCase`, поля `camelCase`, приватные поля без
  префиксов, события `OnSomething`.
- Системы общаются через события и методы менеджеров, без `FindObjectOfType`
  и `GameObject.Find` в рантайме.
- `Debug.Log` с префиксом системы: `Debug.Log("[Sanity] ...")`. Перед сдачей —
  убрать лишний спам.

## 4. Git

- `main` всегда открывается и запускается. Фичи — в ветках `feature/<что>`.
- Коммиты маленькие, сообщение — что изменилось (на английском или русском).
- **Сцену этажа редактирует один человек одновременно** — предупреждать в чате.
  Остальное — в префабах и в своей `Scenes/Sandbox/Sandbox_<имя>`.
- `.meta`-файлы всегда коммитятся вместе с ассетами.

## 5. Чеклист перед PR / пушем в main

- [ ] Проект открывается без ошибок в консоли.
- [ ] У новых классов есть `/// <summary>`, у настраиваемых полей — `[Tooltip]`.
- [ ] Неочевидные места прокомментированы, мёртвого кода нет.
- [ ] Если поменялся дизайн/архитектура — обновлён паспорт.
- [ ] Если появилась новая система — есть `docs/systems/<Система>.md`.
- [ ] Не трогал чужую сцену без договорённости.

## 6. Проверки

Включить один раз на машине (нужны Python 3.8+ и Git LFS):

```bash
git config core.hooksPath tools/hooks
```

После этого перед каждым `git push` запускается [`tools/checks.py`](tools/checks.py).
Те же проверки идут на GitHub для каждого PR в `main` (`.github/workflows/checks.yml`) —
красный крестик в PR = не мержить.

**Блокируют пуш:**

| # | Проверка | Что делать |
|---|---|---|
| 1 | У ассета или папки в `Assets/` нет `.meta`, или `.meta` остался без ассета | Открыть Unity (создаст `.meta`) и закоммитить; лишний `.meta` удалить |
| 2 | Маркеры конфликта `<<<<<<<` / `>>>>>>>` в коде, сцене, префабе | Доразрешить конфликт |
| 3 | Изменения в чужой зоне: ветка `p2/…` трогает папку/сцену P4, `ProjectSettings/` или `Packages/` не из `p1/…` | Откатить и попросить владельца (зоны — `docs/TASKS.md`, раздел 1) |
| 4 | Картинка/звук/шрифт закоммичен не через Git LFS | `git lfs install`, `git rm --cached <файл>`, `git add <файл>` |
| 5 | Ветка отстаёт от `main` | `git pull origin main`, проверить, что всё работает, пушить снова |

Зоны проверяются только для веток `p1/…`–`p4/…`; ветки `main`, `docs/…`, `art/…` — без
проверки зон. Отставание можно временно пропустить: `OW_SKIP_BEHIND=1 git push`.

**Только предупреждают:** `TODO` без имени, класс без `/// <summary>`, закомментированный код.

**Компиляция** — отдельно, потому что Unity нужно 1–3 минуты и закрытый редактор:

```bash
python tools/check_compile.py
```

Запускать перед каждым синком; P1 — перед каждым мержем в `main`. Путь к Unity —
`--unity <путь>` или переменная `UNITY_PATH` (по умолчанию стандартный путь Unity Hub
для 6000.5.6f1).

`git push --no-verify` пропускает хук — только в крайнем случае, на GitHub проверка всё равно сработает.
